RAG MECHANICS & AGENTIC SYSTEMS 5.1 The Fundamental Limits of Pre-trained Large Language Models Pre-trained large language models (LLMs) represent static probabilistic compression engines trained on vast internet-scale textual datasets. While they exhibit remarkable emergent capabilities in semantic reasoning, synthetic code generation, and syntactic manipulation, they suffer from two existential engineering constraints: knowledge cutoff boundaries and hallucinations. A model trained up to a specific calendar epoch possesses zero intrinsic awareness of private enterprise records, internal institutional documentation, or real-time system states. Furthermore, because language models operate via autoregressive next-token prediction, they prioritize linguistic plausibility over factual ground truth. In mission-critical environments—such as grading physics examinations or executing hardware firmware commands—relying on internal parametric memory inevitably produces subtle, catastrophic hallucinations disguised as authoritative answers. 5.2 First-Principles Architecture of Retrieval-Augmented Generation (RAG) Retrieval-Augmented Generation (RAG) represents an architectural paradigm that converts the LLM from a closed-book regurgitation engine into an open-book analytical processor. Instead of requiring the neural network to memorize proprietary datasets within its internal weights, the knowledge corpus is externalized into an indexed database. The complete RAG lifecycle comprises four decoupled phases: 1. Document Ingestion and Text Extraction: Raw files (PDFs, Markdown notes, source code) are stripped of formatting artifacts and converted to UTF-8 plain text. 2. Chunking and Tokenization: Long documents are systematically partitioned into discrete semantic blocks to satisfy context window constraints and prevent information dilution. 3. Indexing and Vector Storage: Chunks are passed through an embedding model that maps the semantic meaning of each block into a high-dimensional vector space, which is indexed in a vector database. 4. Retrieval, Context Injection, and Generation: When a user query arrives, the system retrieves the most semantically relevant chunks from the database, injects them directly into the LLM system prompt, and commands the model to synthesize the final answer strictly using the provided context. 5.3 Chunking Strategies, Window Sizes, and Overlap Economics The chunking phase is the single most critical determinant of RAG accuracy.
